任务二 · creative 电影墙（自学第 7 种效果 + prev / next 说明）

学习路径

打开官方示例 swiper/demo/257-effect-creative.html，让 AI 逐行解释 creativeEffect 的写法后仿写。本页配置：

creativeEffect: {
  prev: { translate: ['-100%', 0, -400], rotate: [0, 0, -12], scale: 0.75, opacity: 0.5 },
  next: { translate: ['100%',  0, -400], rotate: [0, 0,  12], scale: 0.75, opacity: 0.5 },
}

prev / next 的 transform 各控制什么（自己的话）

prev 描述「已经翻过去的那张（左侧离场）」要变成什么样：缩小到 0.75、向左移出自身一个宽度、绕 z 轴转 -12°；next 描述「还没轮到的下一张（右侧候场）」在进场前处于什么状态：缩小、右移、转 +12°。切换时当前张从正常态过渡到 prev 态，下一张从 next 态过渡到正常态——两侧小卡片斜着排开，就像电影选片墙。

答辩备忘

translate 里的百分号是相对 slide 自身的宽/高（'-100%' 就是向左移出一张幻灯片自己的宽度），不是相对父容器；想让卡片转 20° 就把 rotate 的 -12 / 12 改成 -20 / 20。

我：挑一个课堂没讲过的 Swiper 能力加到演示四，我选 keyboard 键盘控制。

AI 第一次给的是 keyboard: { enabled: true } 且 4 个轮播全开——按一下方向键4 个轮播一起动；我改为只挂在 #wySw4，并加 onlyInViewport: true：只有它出现在视口内才响应键盘，避免滚动页面时误触。

答辩四连问备忘

· 代码含义：keyboard 模块把 ← → 映射到 slidePrev / slideNext；
· AI 错在哪：少了 onlyInViewport，且不该给全部轮播开键盘；
· 新参数作用：onlyInViewport 限定"轮播在视口内才响应"；
· delay 演示：把 3200 改成 1000，预期每张只停 1 秒、翻页明显变快。
